# 安全与隐私

本文描述当前实现的边界，不替代威胁建模或安全审计。涉及新增网络端点、写入能力、凭据处理或数据导出时，先阅读本文再实现。

## 数据边界

- 好友、日志、收藏、备注、标签、通知和分析数据保存在本地 SQLite/KV 中。
- 默认数据库路径为 `%APPDATA%\VRCX\VRCX.sqlite3`。
- 数据库备份/恢复通过用户主动选择文件完成。
- 项目不把 VRCX 用户数据上传到第三方分析服务。

应用仍会访问必要的外部服务：

- VRChat REST API 与 Pipeline WebSocket；
- 更新检查和下载（如启用）；
- 用户主动配置的代理、SMTP 或翻译等集成。

## 网络边界

| 通道 | 默认状态 | 说明 |
| --- | --- | --- |
| VRChat API | 登录后使用 | 经 `request()` → `WebApi` → .NET sidecar |
| Pipeline WebSocket | 登录后连接 | 前端 `src/services/websocket.js` 直接连接 |
| MCP HTTP | 默认关闭 | 仅 `127.0.0.1`，端口可配置 |
| 更新/翻译/邮件 | 按设置启用 | 不应读取或上传本地数据库 |

不要新增监听 `0.0.0.0` 的本地服务，也不要把 MCP 暴露到局域网或公网，除非用户明确要求并完成风险评审。

## MCP 边界

- 默认关闭，必须由用户在设置中开启。
- 仅绑定 `127.0.0.1`。
- 工具面向本地 SQLite 查询。
- 当前唯一写工具是 `vrcx_set_note`，只写本地备注。
- 资源列表为 `vrcx://schema/tables` 与 `vrcx://context/server`。
- AI 客户端配置只使用回环 URL，不包含 token 或 Cookie。

新增 MCP 工具时，默认保持只读；新增写入、文件访问、进程执行或网络转发能力必须单独评估权限、审计日志和用户提示。

## IPC 与 sidecar

`dotnet_call` 是前端进入 .NET 的统一通道。调用方不能绕过代理直接执行任意 SQL 或任意系统命令；`Program.cs` 对类名和方法名做分发，SQLite 服务对 SQL 类型和危险语句进行限制。

新增 IPC 方法时：

- 限制可调用的类和方法；
- 对路径、端口、SQL、文件内容做输入校验；
- 保持参数为明确的 JSON 类型；
- 不把本地数据库路径或凭据写入前端日志；
- 为失败路径添加测试和 probe。

## 凭据与日志

- 不在文档、示例、Issue、截图或日志中粘贴真实 token、Cookie、SMTP 密码、代理认证信息。
- API 认证信息只通过现有请求与 sidecar 路径处理，不放入 `localStorage`、源码仓库或第三方遥测。
- Sentry 或其他遥测只在用户同意的范围内运行，提交前检查是否包含个人信息。
- 调试日志应能定位请求和状态，不应打印完整请求头、Cookie 或数据库行。

## 数据库操作

- schema 变更必须幂等、兼容旧库并通过数据库服务迁移路径执行。
- 备份文件可能包含完整社交关系与历史记录，提醒用户妥善保管。
- 导入前应展示冲突策略和影响范围；导入不会把数据发送到外部。
- 禁止为了“修复”数据库直接覆盖用户文件或删除 WAL 文件。
- 数据库损坏、磁盘满、只读和锁定错误应给用户明确提示，并优先建议备份。

## VRChat API 使用

- 只请求应用功能所需的公开数据。
- 遵守现有 429 退避和最小轮询间隔。
- 不实现批量抓取、自动刷、自动加好友、绕过限制或高频并发脚本。
- 不把自动化能力包装成“用户体验优化”来规避 API 约束。

## 发布与供应链

- `Version` 和 `version_channel` 决定发布版本。
- 发布前运行依赖、格式、测试、Tauri 迁移和原生构建检查。
- 不提交安装包、构建目录、调试日志、数据库备份或凭据文件。
- 更新第三方依赖时审阅锁文件变更，不接受无关的二进制或脚本改动。

## 报告安全问题

报告中请提供可复现步骤、影响范围和最小化证据，隐去真实账号数据。不要在公开 Issue 中发布可直接利用的任意文件读取、任意写入或远程访问 PoC；需要私下披露时使用项目维护者提供的安全联系方式。
